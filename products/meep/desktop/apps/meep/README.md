# Meep for macOS

Start PostHog and launch the app using the [local development instructions](../../../README.md#local-development). The desktop connects directly to PostHog with browser OAuth. Credentials are stored in the macOS Keychain; each region, project and user has its own SQLite replica.

From the native workspace (`products/meep/desktop`), run `sh scripts/local.sh --hot` for local hot reloading, or `sh scripts/meep.sh --posthog local` for a release build against local PostHog. The app accepts `local`, `us` and `eu` for `--posthog`. For an issuer requiring a pre-registered public client, place the appropriate `posthog-us-client-id` or `posthog-local-client-id` in the app data directory. The loopback redirect is `http://127.0.0.1:43180/callback`.

To record a demo while you keep using the machine, build with `cargo build -p meep --bin meep --features demo-driver` and start the app with `MEEP_DEMO_SOCKET=/short/path.sock` and `GPUI_DRAW_WHEN_HIDDEN=1`. The app then replays input from that Unix socket into its own window, one JSON object per line (`{"op":"move","x":..,"y":..}`, `down`, `up`, `scroll`, `text`, `key`; positions are window points), draws a cursor where the replayed pointer is, keeps drawing while other windows cover it, and does not take focus when it starts. Record the window with any capture that reads a covered window's contents; ScreenCaptureKit only delivers frames while the window is composited.
