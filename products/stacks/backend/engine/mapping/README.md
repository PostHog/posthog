# Kind mappings

Each JSON file describes one definition kind. `api_schema` names its create schema. `resource_type` and `id_type` select the implementation and preserve the JSON type of references. `fields` maps dotted body paths to attributes. `json_fields` marks JSON-encoded paths, and `set_fields` marks unordered collections. `read_api` declares the collection, detail key and field projections for reading entities.

`hook` handles composed fields. Dashboard tiles become an ordered layout, and insights carry their dashboard IDs. Event `property_groups` become individual memberships. Removing one membership detaches that group. Releasing the event preserves its memberships and enforcement settings. Models send materialization, schedule and incremental settings. `typed_only` fields, including model columns and property enums, describe SDK types. A source's `public_inputs` lists connection fields that accept literal strings. Other string inputs require named secrets. An omitted or empty schema selection enables discovery.

`unmanaged` maps fields PostHog owns to attributes, or to null when there is no attribute. `ignore_attributes` covers additional attributes editable in PostHog. `defaults` supplies creation values. Flags start disabled when `active` is omitted. Creation uses the configured `active` value and full `filters` document. Afterwards PostHog owns `active` and release conditions. The mapping's `owned_filter_keys` lists the filter keys the definition can own: `multivariate` and `payloads`, each only when configured. PostHog starts experiments in draft and manages their lifecycle. A definition can set a conclusion or conclusion comment once the experiment has stopped. `gaps` explains unsupported fields, and `accepted_defaults` records defaults that already match the supported behavior.

Definition-level `depends_on` lists other definitions in the same stack by kind and key. The engine checks these edges together with body references. It uses them to order creation and reverse the order for removal. They stay outside the API body and field ownership.

`natural_key` specifies the body field and collection to search before creation. `key_pattern` matches the whole key. `key_max_length` counts Unicode code points. `reserved_keys` and `reserved_key_prefixes` list names the API reserves. `key_sources` names the API files behind each rule. `import_id` selects by ID or name. Name-based adoption verifies the returned UUID. A survey looks up its unique body name and keeps its author's slug, so its lookup sets `definition_key: false`. A check adopts by assertion fingerprint. `loses` describes the effect of recreating a kind.

`PROVIDER_VERSION` in `mappings.py` pins the build. Conformance tests compare `provider_schema.json` with the binary and body fields with their Zod schemas or the property group serializer.

## Ownership and diffs

Pass every binding, including ones whose definitions have disappeared, as `{kind, key, entity_id, status?, origin?}`. Status defaults to `bound` and can be `pending` or `detached`. Origin defaults to `created`. Preserve `adopted` by entity ID after import, partial push and rename. The local script persists origin alongside its record. The service must also persist it because `read_bindings` can only recover identities and IDs.

Supply verified natural-key matches as `existing: [{kind, key, entity_id}]` or let the engine look them up. Pass other stacks' pending and bound entities as `claimed: [{kind, entity_id, stack, repository}]`, refreshed before diff and push. The service reserves competing claims atomically. A conflict names the owning stack and repository. Pass detach requests as `[{kind, key}]`.

Adopted entities, explicit detaches and kinds with `removal: "prevent"` release. Events keep their definitions. Property groups release because deleting one cascades to its properties and event links. Checks release because their create operation can adopt an existing assertion. Created models, endpoints and metrics allow soft deletion. Model and endpoint removal also reverts materialization and checks downstream dependencies.

An external deletion sets `drift[].deleted`. A remaining definition creates a new entity or adopts an unclaimed natural-key match. Computed-only updates count as updates with an empty `fields` list.

An `adopt` change carries the entity's PostHog ID as a string so the service can reserve it before push. Switching between a literal group ID and a reference to the same group preserves the existing event membership. Fields listed in `managed_when_set` belong to code only when their values are present and non-null. This includes event metadata, survey start, end and sampling start dates, survey appearance, and the conclusion and conclusion comment on a stopped experiment.

A context page's key and binding ID are its full wiki path. Its mapping sets `ownership_scope: "organization"`. Require explicit organization-wide authorization for this kind and reserve the path across all projects of that organization. Pass claims from those other projects to the engine. The default ownership scope for other mappings is the project.

Diff adopts an existing page and shows both versions of any changed Markdown in its `content` field row. A push writes against the reviewed wiki revision. Writes from the same push advance that revision, and an external change requires a fresh diff. Releasing a page leaves its published Markdown in the wiki. Pulling explicit paths uses the project's page route. Listing all pages uses the organization's wiki tree and requires a credential allowed on organization routes.

## Service boundary

`validate_key(kind, key)` returns the same key error as `translate_in`, or `None` when the key is valid. `owned_fields(kind, body)` returns the body paths to compare in the managed-write guard. Pass the bound definition's body. A false boolean or empty tag list is an explicit value. An omitted or null event setting is editable in PostHog. Tile and membership fields participate when declared, and a source with automatic table discovery leaves its schema selection editable. Nested paths such as `threshold.configuration.type` refer to nested request fields.

`natural_key_kinds()` returns the kinds whose definition key identifies the same entity across stacks. `read_entities(kind, credentials, *, ids=None, cursor=None, limit=100)` returns `{results: [{entity_id, name, body}], next_cursor}`. Use the returned cursor to continue. Explicit IDs preserve order. Related entities retain literal IDs. Stored destination inputs, schema defaults and source connection settings are omitted. Supply named secret references when adopting an entity that requires credentials.

Pass stack secrets in `credentials["secrets"]` as a mapping of names to values. An absent name produces `secret_missing` before project reads. The caller supplies the execution credential. The PostHog API enforces managed-in-code writes and the stack credential's exemption.

`validate_description(description, bindings)` checks the same definitions as `translate_in` in memory before storage. It returns an empty list on success or the first error. The limits are 2,000 definitions, 5 MiB of compact JSON and 32 levels including the envelope. `secret_inputs` declares sensitive destination input names, schema markers and template-specific fields. These rules also apply to mapping overrides and input defaults. Source credentials can be nested, with public connection fields and discriminators listed in the source mapping. A literal in a secret-bearing position returns `secret_literal` with the kind, key and path.

`run_push(..., on_record=save)` calls `save(bytes)` synchronously for each valid record write on a private listener thread and again at the end on the caller's thread. Raising `AbortRun` stops the process group before acknowledging the write. The latest valid record is delivered again before the exception reaches the caller. Any other callback exception lets the push finish and is re-raised after final delivery and cleanup. Several operations can finish between writes. A hard kill can lose work since the last write. Older saved diffs using a local backend deliver their recovered final record.

`timeout_seconds` is a positive finite number, default 900. The local command accepts `--timeout-seconds`. One deadline covers lookup and all subprocesses for each diff or push. A timeout kills the process group. Python cleanup removes the private run directory on normal exit and interruption. After a hard kill or host failure, stop the abandoned processes and sweep `stack-*` under the work directory. It can hold secret inputs, a saved diff or a partial record. Save any partial record and run diff again before retrying.

## Execution scopes

Each mapping's `scopes.read` and `scopes.write` list scope objects from `posthog/scopes/catalog.py`. `kind_scopes(kind)` returns the sorted `:read` grants for a diff and the full sorted set of `:read` and `:write` grants for a push. The service takes the union across definitions and existing bindings. A kind has one declaration for all its supported definitions, so an optional dependency also contributes its scope when the field is absent.
