_perspective: review-hog-blind-spots-general · directly-related: True_

- **Found:** The race is real and the consequence is the security invariant the codebase elsewhere treats as must-handle. Sequence: run R (head H1) passes `post_verdict`'s head check while the head is still H1 → the opt-out push lands and the skip path runs the dismissal sweep at T1 (R has not yet posted, so R is not dismissed) → R posts its GitHub approval at T2 against the now-stale H1. Narrow interleaving window, but a broken security invariant, and the fix is small, consistent with existing precedent, and testable.
- **Priority:** `should_fix` stands — a real correctness gap in the approval-invalidation path with a security-relevant consequence, but reachable only via a specific interleaving and self-healing on the next head-changing event, so it does not rise to `must_fix`.
