# 2026-10-02: emission on Sonnet 5.5

Follow-up to [2026-10-02.md](2026-10-02.md), which kept the emission model on `claude-sonnet-5`.
This change moves pre-emit summarization and actionability to `claude-sonnet-5-5`, with three changes that make that safe:

- A model refusal in `check_actionability` now drops the record, where it used to fail open.
- The ticket and issue actionability prompts mark two more kinds of record NOT_ACTIONABLE: dissatisfaction that names no specific page, feature, action, or error, and a report that contradicts itself or takes its complaint back.
- The grouping fixture relabels groups 15, 32, and 33 as actionable, because the written policy calls product questions, misread features, and setup problems ACTIONABLE.

## Data

| Set                     | Cases                      | Role                                                    |
| ----------------------- | -------------------------- | ------------------------------------------------------- |
| Grouping fixtures       | 92 gated signals, 3 passes | Development set, used to tune the prompt                |
| `actionability_data.py` | 64 invented cases          | Held out, written from the policy before any tuning ran |
| Hedged-report probe     | 6 cases, 5 passes, scratch | Guard against dropping hedged but specific reports      |

The held-out cases were written by a separate agent that read the policy, not the prompts or the grouping fixtures.
Its labels are unreviewed by a second person.
The probe is not committed.

## Prompt iterations

Sonnet 5.5, medium effort, refusals counted as dropped.
"Admitted" counts NOT_ACTIONABLE calls the gate let through; "dropped" counts ACTIONABLE calls it rejected.

| Variant         | Dev: vague and contradictory admitted | Held out: admitted | Held out: dropped | Probe: dropped |
| --------------- | ------------------------------------- | ------------------ | ----------------- | -------------- |
| Old prompts     | 12/12                                 | 33/84              | 0/108             | not run        |
| v1              | 11/12                                 | 2/84               | 0/108             | not run        |
| v1, no examples | 12/12                                 | 4/84               | 0/108             | not run        |
| v2              | 3/12                                  | 15/84              | 0/108             | not run        |
| v3              | 3/12                                  | 5/84               | 0/108             | not run        |
| v4              | 0/12                                  | 4/84               | 0/108             | 2/30           |
| v5 (shipped)    | 3/12                                  | 9/84               | 0/108             | 0/30           |

- The examples in the vague-complaint rule carry weight: without them the development set does not move.
- An example of a retracted complaint inside the contradiction rule made the model miss every held-out contradiction (v2), so retraction is its own bullet.
- v4's retraction bullet dropped a hedged report ("could be working as intended, but the survey appears again") in 2 of 5 passes. v5 states that a hedged report that names a specific problem stays ACTIONABLE.
- Every remaining held-out miss is a self-contradictory report, which still names a real feature.
  The development set has one contradiction case, so tuning further would mean tuning on the held-out set, and the prompt stops here.

## End to end

`eval_grouping_e2e.py`, two runs, all stages on Sonnet 5.5, scored with the relabeled ground truth.

| Metric                                   | Emission on 5.5, old prompts, fail-open | This change  |
| ---------------------------------------- | --------------------------------------- | ------------ |
| Vague and contradictory signals admitted | 4/4, 4/4                                | 1/4, 1/4     |
| Actionable signals dropped               | 0, 0                                    | 0, 0         |
| Unsafe signals admitted by pre-emit      | 17/24, 17/24                            | 9/24, 8/24   |
| Unsafe signals reaching a report         | 1/24, 1/24                              | 1/24, 1/24   |
| Grouping ARI                             | 0.770, 0.778                            | 0.787, 0.808 |
| Cost per run                             | $3.03, $2.92                            | $2.83, $2.68 |

Pre-emit drops more of the unsafe fixtures because a refused record no longer passes.
The safety filter and report judge still catch the rest, so the leak rate does not change.
The ARI spread stays inside the run-to-run noise of earlier reports.

## Not checked

- Production traffic. A stricter gate means fewer signals, and the share of real tickets that the new rules drop is unmeasured.
- Summarization quality on Sonnet 5.5. No eval scores it.
- The managed prompts. A `production` version of a `signals-actionability-*` prompt in prompt management overrides the bundled text, so the new rules reach production only once someone publishes them there.
