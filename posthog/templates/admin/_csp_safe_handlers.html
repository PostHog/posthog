{% comment %} Admin pages serve a CSP whose script-src carries no 'unsafe-inline' and no 'unsafe-hashes', so an inline onclick or onsubmit attribute is dropped. That policy is enforced for every staff member rather than flag-gated, so a confirmation written as onclick="return confirm(...)" never runs and the destructive action fires unguarded. Include this once per admin page and mark the controls instead:
Both handlers are delegated from the document, so a control rendered later — a readonly-field widget the admin injects into a change form — is covered without its own script block. The include is idempotent for the same reason: a page that pulls it in more than once still binds once, and a second confirmation prompt would be worse than none. Every template that includes this must be rendered with the request in context, or {{ request.csp_nonce }} resolves empty and the block is refused like the attribute it replaces. A render(request, ...) call already does that. A render_to_string(...) call must pass request=getattr(self, "_current_request", None) explicitly. {% endcomment %}
