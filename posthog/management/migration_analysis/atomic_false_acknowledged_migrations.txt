# Migrations acknowledged to run with atomic=False and no CONCURRENTLY op (AtomicFalsePolicy).
#
# atomic=False drops per-migration transaction rollback safety, so a failure midway leaves
# partial changes committed and a bin/migrate retry re-runs the whole migration. That is only
# safe when the migration's operations are idempotent (a re-run is a no-op on already-applied
# rows). The usual reason to want it is a long-running data migration that commits in batches
# so it never holds locks or bloats WAL for one giant transaction.
# Before adding a line here, prefer keeping the migration atomic (the default) if the data
# volume is small, or moving a genuinely large backfill to an async migration.
# Adding a line means: I understand this migration runs without transaction rollback safety,
# and its operations are idempotent so a bin/migrate retry after a partial failure is safe.
# Format: one "<app_label>.<migration_name>" per line, e.g.
# posthog.1234_backfill_something_in_batches
# Does run CONCURRENTLY, one index per sourcebatch partition, but from RunPython
# (the partition list is only known at runtime), which the type-based check can't see.
warehouse_sources_queue.0008_sourcebatch_superseded
warehouse_sources_queue.0009_sourcebatch_job_id_idx
# Scans every flag row but writes only the few hundred that need cleaning, each as its own
# compare-and-swap. Atomic would hold one transaction open across the whole scan, pinning xmin
# on the table the flags API writes to. Re-running is a no-op: the transform is idempotent and
# each swap only matches rows still holding the pre-clean value.
# Same shape as 0014: scans every flag but writes only the few that need clamping, each as its
# own compare-and-swap. Re-running is a no-op, since a clamped set already sums to 100.
feature_flags.0015_clamp_rollout_percentages_over_100
# Backfills one search row per canvas in batches, so a long run does not hold one transaction open.
# Re-running is a no-op: bulk_create passes ignore_conflicts, and the unique key is (team, kind, source_key).
tasks.0120_backfill_canvas_search_documents
# Fills the generic tag pointer in batches of 10,000 rows, so the run never holds one transaction open.
# Re-running is a no-op: each UPDATE only touches rows whose content_type_id is still NULL.
posthog.1370_backfill_taggeditem_generic_pointer
# Fills the actionability cache for reports judged before the columns existed, in id-ordered
# batches so no single transaction locks the whole backlog. Re-running is a no-op: a pass only
# selects reports that still hold no cached judgment, and each value is recomputed from the
# artefact log.
signals.0154_backfill_report_actionability
# Drops the 13 legacy tagged item foreign keys one per transaction, so each drop locks one busy parent and
# the child instead of all 14 tables at once. Re-running is a no-op: DropForeignKey reads what is left from pg_constraint.
posthog.1383_taggeditem_untrack_legacy_keys
ee.0064_split_identity_provider_config_scopes
