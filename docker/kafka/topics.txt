# Kafka topics the local stacks pre-create (docker-compose.dev.yml and docker-compose.hobby.yml).
#
# Redpanda runs with auto_create_topics_enabled, but that only fires on a producer-first
# write. Two kinds of consumer start before any producer and need the topic to exist:
#
#   * Consumer-only services error at startup on a missing topic.
#   * A ClickHouse Kafka table whose topic is absent never gets a partition assignment. It
#     holds a thread and repeats the request for as long as the server runs, which writes a
#     "Can't get assignment" warning every time and floods clickhouse-server.log.
#
# posthog/clickhouse/test/test_schema.py checks that every topic a Kafka table in schema.py
# consumes appears below. Topics that only a migration creates have no such guard, so add
# them here by hand.
