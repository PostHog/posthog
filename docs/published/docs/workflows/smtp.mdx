If an app can send email over SMTP, it can send through PostHog with no code change. The emails appear in the transactional email log and follow your suppression list and sending limits.

## Connection settings

| Setting    | Value                                                           |
| ---------- | --------------------------------------------------------------- |
| Host       | Shown on the **SMTP** tab in **Transactional**                  |
| Port       | `465` or `587`. If your host blocks them, use `2465` or `2587`. |
| Encryption | TLS or STARTTLS, version 1.2 or newer. Both work on every port. |
| Username   | `posthog`. Any username works.                                  |
| Password   | A project secret key with the `transactional_email:write` scope |

The **SMTP** tab can create a key and send a test email. The From address must be on a domain verified on the **Channels** tab.

Some hosts block the usual SMTP ports, and the connection then times out. DigitalOcean is one of them: use `2587`. If a host blocks every SMTP port, send through the [API](/docs/workflows/transactional-emails) instead.

## What happens to your message

- **Each address in To gets its own email**, so recipients can't see each other. Cc and Bcc addresses get one copy, with the first email.
- **Opens and clicks aren't tracked**, so single-use links stay intact. To track them, add the header `X-PostHog-Capture-Engagement: true`.
- **These headers are forwarded:** `In-Reply-To`, `References`, `List-Unsubscribe`, `List-Unsubscribe-Post`, `List-Id`, and up to 10 of your own `X-` headers. `X-PostHog-` and `X-SES-` headers are reserved. The **SMTP** tab lists other headers it couldn't send.
- **Attachments can be up to 10 MB in total**, and a whole message up to 15 MB.
- **Emails group under the `smtp` key** in the log. To group them under another key, add the header `X-PostHog-Template-Key: order-shipped`.
- **A retry doesn't send twice** when the message has the same `Message-ID`, or the same `PostHog-Idempotency-Key` header. `Resend-Idempotency-Key` works too. A client that builds a new `Message-ID` for each retry needs the header.

`250` means PostHog queued the email, not that it was delivered. Delivery shows in the log.

## Reply codes

PostHog answers within a few seconds of the end of the message, for the whole message. A `4xx` is safe to retry unchanged, and a `5xx` means something must change first.

| Code         | What it means                                                              | What to do                                               |
| ------------ | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| `250`        | Queued                                                                     | Nothing                                                  |
| `421`        | Too many connections, a slow upload, or PostHog is restarting              | Reconnect shortly                                        |
| `451`        | Rate limit, quota, PostHog is busy, or it couldn't confirm the send        | Retry with the same message                              |
| `454`        | PostHog couldn't check your key, or it failed too many times               | Follow the reply text                                    |
| `530`, `538` | No login, or a login before TLS                                            | Turn on TLS or STARTTLS, and set a username and password |
| `535`        | The key is wrong, lacks the scope, or SMTP isn't on for the project        | Check the key                                            |
| `550`        | The sender isn't verified, or a recipient is suppressed or can't get email | Follow the reply text                                    |
| `552`        | The message or its attachments are too large                               | Link to large files                                      |
| `553`        | PostHog can't send to this address                                         | Check the address                                        |
| `554`        | A blocked file type, too many recipients, or sending is suspended          | Follow the reply text                                    |

If some addresses in To are refused and others are queued, the reply is `250`, and the **SMTP** tab lists the refused ones.
