# Warehouse source defect catalog

One entry per shipped defect: what was wrong, how it was actually discovered, and the evaluation step that would have caught it before merge.
Distilled from the August 2026 fix wave across Checkout.com, Gladly, Decagon, App Store Connect, Meta Ads, and the credential/scope cluster.
Extend this file whenever an evaluation finds a defect, one escapes to production, or a Self-driving inbox report (the data-warehouse scout, health checks) traces back to source code — it is the institutional memory the tiers in `SKILL.md` are built from.
Several discovery stories below predate that scout: the manual audits they describe (`Completed` over zero rows, silent staleness behind a green status) are now its standing sweep signatures, which is why the post-merge tier hands the watch to Self-driving.

Entry format: **PR — defect. Discovery. Catch.**

## Class 1 — inferred vendor contract

The code's model of the API came from docs, SDKs, or another connector; the real API disagrees; the fixtures encode the same wrong model, so tests pass.

- [#79119](https://github.com/PostHog/posthog/pull/79119) — Checkout.com payments search omitted the vendor-required non-empty `query` field; every request 422'd, four tables synced zero rows for every account. Contract taken from vendor SDKs, never fired live; error logs kept only the status line, so undiagnosable. Discovery: customer report. Catch: one authenticated request per endpoint; log a bounded response-body excerpt on API errors.
- [#82961](https://github.com/PostHog/posthog/pull/82961) — customers/instruments fan-out required prefixed ids the real search response never carries; both tables landed nothing for every account while reporting `Completed`. Fixtures contained the ids the live API never sends. Discovery: production data audit. Catch: parse a captured real payload with the source's own parser; forbid zero-rows-plus-`Completed` per enabled table.
- [#78129](https://github.com/PostHog/posthog/pull/78129) — Decagon pagination read `next_page_cursor`; the vendor's docs name the cursor three different ways and the live API sends another; every sync fetched one page and reported `Completed`. Discovery: customer compared counts with the vendor dashboard. Catch: live first sync asserting row count > page size and ≈ vendor-reported total; warn when a walk ends on a full page without a cursor.
- [#78983](https://github.com/PostHog/posthog/pull/78983) — Gladly org cleaning truncated at the first dot and rejected dots, so region-sharded orgs (`myorg.us-1.gladly.com`) could never connect in any input form. Discovery: support thread. Catch: parameterize host construction over every vendor-documented domain shape; credential-free DNS/401 probe of each.
- [#78038](https://github.com/PostHog/posthog/pull/78038) — hardcoded `.gladly.com` meant sandbox orgs (`gladly.qa`) could never authenticate; no test asserted the probe URL, so a silently ignored domain field would have passed everything. Catch: assert the exact URL the probe hits; allowlist domains before interpolating into a hostname (SSRF containment).
- [#82159](https://github.com/PostHog/posthog/pull/82159) — a non-CSV report body (HTML error page, leading blank line) still "parsed": line 1 became the header, rows reached the pipeline, and the user saw a misleading downstream error. Discovery: production sync failure. Catch: malformed-body fixtures asserting a loud, named header error; require the cursor and PK columns in any parsed header.
- [#79829](https://github.com/PostHog/posthog/pull/79829) (design catch, pre-merge) — the issue's assumed flat `/verifications` endpoint does not exist, and `include=` is rejected on list endpoints; caught during implementation by probing, not after. Lesson: endpoint existence is a claim like any other.
- [#82958](https://github.com/PostHog/posthog/pull/82958) (design catch) — the issue pointed at a deprecated v2 endpoint that only accepts a key type the source doesn't store; implemented against v3 instead. Lesson: verify the endpoint's auth acceptance for the credential the source actually holds.
- [#79826](https://github.com/PostHog/posthog/pull/79826) — shipped with an explicitly open question (is `KEYWORD` a report field or breakdown-only?) because vendor docs were unreachable from the sandbox; chose the loud-failure interpretation. Lesson: when a claim can't be verified, pick the shape whose wrong-guess outcome is loud, and flag it for a live-access reviewer.

## Class 2 — silent success

A code path returns normally while landing less than the vendor holds; status says `Completed`.

- [#78127](https://github.com/PostHog/posthog/pull/78127) — Netlify `GET /sites` without `filter=all` returns only personally-owned sites; for team tokens, `sites` and all four fan-out schemas synced zero rows yet reported `Completed`. Discovery: support escalation. Catch: live sync with a team-owned token; treat "Completed with 0 rows" as a defect signal.
- [#82115](https://github.com/PostHog/posthog/pull/82115) — Checkout.com budget exhaustion set a flag and returned; a generator that returns normally is a successful sync, so whole months were missing under a green status. A unit test pinned the wrong "stops cleanly" contract. A search horizon also silently clamped every configured `start_date`. Discovery: customer report, then manual audit. Catch: exhaustion raises a typed retryable error; horizons are defaults, never clamps; per-month parent/child coverage invariant (the fix shipped the SQL — see invariant-queries.md).
- [#82957](https://github.com/PostHog/posthog/pull/82957) — report files whose row widths disagreed with the header skipped every row with only warnings; months of legacy-era files parsed to zero rows silently. Discovery: production audit. Catch: format-era fixture corpus; invariant "every listed file with data rows loads ≥1 row"; cap the skip ratio and raise past it.
- [#80184](https://github.com/PostHog/posthog/pull/80184) (caught in review) — pagination counted discarded duplicate rows toward the server-reported total, terminating early and silently omitting rows. Catch: terminate on rows kept, not rows fetched, plus a no-progress guard.
- [#82273](https://github.com/PostHog/posthog/pull/82273) — the bulk schema-update API silently dropped `primary_key_columns` (never declared on the serializer; DRF discards unknown fields) and returned 200 with nothing changed. Discovery: operator remediation path went nowhere. Catch: bulk/single serializer field-parity test; assert post-call DB state, never just the status code.
- [#82956](https://github.com/PostHog/posthog/pull/82956) — App Store Connect acquisition-attribution columns exist only in "Detailed" report variants the source never requested; most of the vendor's rows had no destination table. Discovery: customer reconciled against a rival pipeline. Catch: reconcile discovered streams against the vendor's full report catalog; exact-name variant lookup with no suffix-less fallback.

## Class 3 — credential-instance variance

Correctness is a function of the credential: key type, per-endpoint scopes, plan tier, OAuth manifest, token identity, region.

- [#78033](https://github.com/PostHog/posthog/pull/78033) — Twilio validation probed an endpoint that Standard/Restricted API keys are denied on, so the documented happy path could never pass; a test row encoded the wrong assumption. Discovery: customer setup attempt. Catch: validate with every key type the vendor issues; probe ladder over data resources rather than one privileged endpoint.
- [#78035](https://github.com/PostHog/posthog/pull/78035) — SendGrid scopes are per-endpoint but the source never probed them; tables looked reachable, then first sync 403'd and paused. One table also required a product tier, and legacy accounts serve a different API entirely. Discovery: CSM-escalated paused sync, then fleet triage. Catch: per-table scope probe using each endpoint's own params; matrix cells for missing-scope keys, missing product tier, legacy account.
- [#78134](https://github.com/PostHog/posthog/pull/78134) — Klaviyo 403 means missing scope _or_ plan-gated add-on; the error advised granting scopes the key already had, and `raise_for_status()` dropped the disambiguating body. Discovery: support report. Catch: matrix cell for an account without the add-on; append the error-body detail; order plan-gating matchers ahead of blanket 403; plan-gated tables default off.
- [#77920](https://github.com/PostHog/posthog/pull/77920) — the Stripe App OAuth manifest requested read permissions for a third of the tables the connector advertises; OAuth users saw most tables permanently greyed out, with no user-side lever. Two webhook permissions had also been silently dropped in an unrelated reformat. Discovery: customer report. Catch: test-mode OAuth install asserting every advertised table passes its probe; manifest ↔ endpoint-catalog diff as a test.
- [#80824](https://github.com/PostHog/posthog/pull/80824) — one field list still requested four `business_management`-gated fields while OAuth grants only `ads_read`; Meta rejects the whole field set, so the table 403'd every sync, and the surfaced advice ("re-authorize") could never fix it. Root cause included two parallel field lists that drifted. Discovery: customer issue. Catch: live single-object read per node with the minimum-scope token; consistency test across duplicated field lists; error copy must name an action that can work.
- [#78034](https://github.com/PostHog/posthog/pull/78034) — one generic "Invalid Gladly credentials" string covered bad token, missing permission, wrong subdomain, unreachable host, and vendor outage. Discovery: customer report that couldn't be diagnosed remotely. Catch: simulate each failure class against the probe and assert distinct, actionable messages.

## Class 4 — keys, merges, partitions, restatements

Only breaks across overlapping runs, regenerated files, drifting fields, or days of vintages — invisible to single-pass tests.

- [#82959](https://github.com/PostHog/posthog/pull/82959) — `primary_keys=["id"]` yet duplicate ids landed: Delta merge matches key AND partition, and the partition was derived from a mutable, sometimes-missing served field, so a drifted row landed in a second partition the merge never matched. Small enough in proportion to go unnoticed. Discovery: production `count()` vs `uniqExact(id)` audit. Catch: partition must be a pure function of the immutable PK (`md5(id)` bucket pattern); post-sync PK-integrity invariant on every table.
- [#82099](https://github.com/PostHog/posthog/pull/82099) — positional key `(file_id, file_row_index)` on report files the vendor regenerates daily over overlapping ranges: every regeneration landed a fresh copy of each row, overstating any `SUM()`; restatements carry different amounts so post-hoc dedup can't repair it. Discovery: customer's sums were too high. Catch: regeneration-replay fixture (two overlapping generations → keep-last by business key); raise when a file's header lacks the key column.
- [#82974](https://github.com/PostHog/posthog/pull/82974) — App Store Connect restates each report date for ~6 days and the source retains every vintage; a naive `SUM(...) GROUP BY date` overcounts several-fold with no error. An `is_latest` flag is provably impossible under the merge write path, so dedup recipes ship in table/column descriptions instead. Discovery: measuring warehouse output against known-true numbers. Catch: multi-vintage fixture asserting the published dedup recipe returns truth; restatement-sanity invariant (naive vs deduped sum).
- [#82973](https://github.com/PostHog/posthog/pull/82973) — report files carry no types, so everything landed as strings; `MM/DD/YYYY` dates sort wrong lexically and range filters silently return incorrect rows. Typing at ingest only applies to newly created tables: existing Delta tables cast typed values back to string, leaving mixed formats. Discovery: consumer pain, deferred issue. Catch: semantic per-column-class assertion (date range over a month boundary); brownfield append-to-existing-table fixture.
- [#80027](https://github.com/PostHog/posthog/pull/80027) (known accepted hazard) — synthetic row-hash PKs over rows containing display names: a rename changes the hash on re-read, creating bounded duplicates. Lesson: hash only stable fields; document accepted hazards in the PR.

## Class 5 — environment and pre-existing state

Works in a clean-room test environment; fails in production topology or against data that already exists.

- [#80823](https://github.com/PostHog/posthog/pull/80823) — every production Framer connect failed from the day the source shipped: production egress rides a CONNECT proxy answering `HTTP/1.0 200 OK`, which the `websockets` library rejects; `requests`/urllib3 tolerate it, which is why every HTTP source works. Tests used fake servers with no proxy in the path. Discovery: production failure report, reproduced locally against a goproxy-style proxy. Catch: run `validate_credentials` through a proxy speaking exactly that dialect for any non-`requests` transport, pre-merge.
- [#84705](https://github.com/PostHog/posthog/pull/84705) — Redshift materialized views were classified as tables (Redshift exposes no `pg_matviews`), with no row counts and a dead-end "add a primary key" warning for a key that cannot exist. Discovery: operator confusion. Catch: per-engine introspection conformance check — create table/view/matview on a real cluster of that engine and assert discovered type, counts, and messaging.
- [#84740](https://github.com/PostHog/posthog/pull/84740) — `information_schema.table_constraints` returns only rows the role has privileges on; zero rows means "no key" or "no privilege", and the code asserted the first, so restricted-role customers saw hundreds of tables failing with a false "no primary key". Composite keys were also assembled in undeclared column order. Discovery: production symptom, split-brain across tables on one source. Catch: restricted-role fixture asserting "undetermined", not "absent"; capability probe before interpreting empty results; explicit `ORDER BY ordinal_position`.

## Design patterns that pre-empted defects (worth copying)

From the feature PRs of the same wave — decisions that made unverifiable claims safe instead of wrong:

- **Safe-guess engineering**: when a param's type/behavior is undocumented, choose the interpretation whose wrong-guess outcome is loud (4xx) or degrades to a correct-but-slower path (ignored filter + merge semantics), never one that silently loses rows ([#80186](https://github.com/PostHog/posthog/pull/80186), [#79826](https://github.com/PostHog/posthog/pull/79826)).
- **Opt-in defaults** (`should_sync_default=False`) for tables that are plan-gated, PII-bearing, unbounded-size, or shape-unverified ([#80028](https://github.com/PostHog/posthog/pull/80028), [#80187](https://github.com/PostHog/posthog/pull/80187)).
- **No guessed primary keys**: keyless beats a composite that silently merges distinct rows; synthetic hashes cover only stable fields ([#80183](https://github.com/PostHog/posthog/pull/80183), [#80000](https://github.com/PostHog/posthog/pull/80000)).
- **Exclusive window bounds for keyless append streams**, inclusive+merge for keyed ones, so boundary seconds neither duplicate nor drop ([#80183](https://github.com/PostHog/posthog/pull/80183)).
- **Truncation warnings near vendor row caps**, and windows sized so caps are unlikely to bind ([#80027](https://github.com/PostHog/posthog/pull/80027)).
- **Fail-loud parse guards with bounded tolerance**: normalize what the header itself explains, raise on data-rows-but-zero-parsed, cap the skip ratio ([#82957](https://github.com/PostHog/posthog/pull/82957)).
- **Webhook-only history tables** flagged so a scheduled full refresh can't truncate immutable history ([#80031](https://github.com/PostHog/posthog/pull/80031)).
- **Docs as part of the definition of done**: every scope, key type, plan gate, and domain quirk discovered during evaluation lands in the public source doc in the same wave ([posthog.com#19254](https://github.com/PostHog/posthog.com/pull/19254), [#19255](https://github.com/PostHog/posthog.com/pull/19255), [#19259](https://github.com/PostHog/posthog.com/pull/19259), [#19261](https://github.com/PostHog/posthog.com/pull/19261)).
